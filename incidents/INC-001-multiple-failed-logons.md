# INC-001 — Multiple Failed Logons

**Status:** RESOLVED / CLOSED  
**Trigger:** DET-001 — Multiple Failed Logons  
**Host:** WIN11-SOC-01  
**Target account:** WIN11-SOC-01\soclab  
**Final disposition:** BENIGN / CONTROLLED SIMULATION — HIGH CONFIDENCE  
**Severity:** Low

## Initial Signal

DET-001 identified a burst of Windows Security Event ID 4625 failures against the same local lab account. The detection produced three failed logons inside a rolling five-minute window.

## Authentication Evidence

The failed-logon events shared the following context:

- Event ID: `4625`
- Logon type: `2` — interactive logon
- Failure reason: `Unknown user name or bad password`
- Status: `0xC000006D`
- Sub-status: `0xC000006A`
- Source: local loopback (`::1`)

Because `soclab` had already been verified as a valid local account, `0xC000006A` was interpreted as a valid account with an incorrect password rather than an unknown account.

## Timeline

The detection cluster occurred over approximately **3.622 seconds**:

| Sequence | Event | Interpretation |
|---|---|---|
| 1 | PowerShell 4104 | Controlled credential-based process attempt initiated |
| 2 | Windows Security 4625 | Authentication rejected for the target account |
| 3 | PowerShell 4103 | Credential rejection recorded |

The same three-event sequence repeated three times. Each 4625 was correlated within milliseconds with a PowerShell credential attempt and rejection.

## Cross-Source Assessment

The investigation did not stop at the 4625 events. PowerShell Operational telemetry showed that each failure followed a controlled `Start-Process -Credential` attempt using intentionally incorrect credentials. No successful child process was created because credential validation failed before execution.

This cross-source correlation substantially reduced ambiguity compared with looking at Windows Security telemetry alone.

## MITRE ATT&CK

**T1110.001 — Password Guessing** under Credential Access.

The mapping describes the repeated password-guessing behavior observed by the detection. It does **not** imply that the controlled test was an actual brute-force attack.

## Final Disposition

**BENIGN / CONTROLLED SIMULATION — HIGH CONFIDENCE.**

The alert was generated by intentionally controlled wrong-password tests against the isolated lab account. There was no successful authentication, compromise, or follow-on execution.

## Detection Tuning Lessons

- Separate target account from caller/subject account.
- Preserve `Status` and `Sub_Status` to distinguish wrong-password from unknown-account failures.
- Treat local loopback as context, not an automatic benign verdict.
- Production thresholds should be based on environment baselines rather than the lab's low validation threshold.
- Correlate repeated authentication failures with process and PowerShell telemetry before final disposition when possible.
